# うまくいった流れをスキルにする

`docs/video-ai/11-claude-higgsfield-canvas.md` の §2 ⑤ と `09-genre-playbook.md` §4.5（自動化が止まる理由）に沿って進める。返答は日本語、普通の文で。

## 手順
1. この案件で通った流れを振り返り、次を集める。分からない所は推測で埋めず、ユーザーに聞く。
   - 使ったモデルと設定（Higgsfield のモデルID、モード、秒数、解像度、縦横）
   - 参照素材とその役割（顔、商品、場所、声、曲）
   - 通ったプロンプト（全文）と、通るまでの回数
   - 迷った場面と、そこで選んだもの、その理由
   - 費用（1回あたりと合計）
   - 検品で見た所と、見つかった崩れ
2. 下の雛形で `.claude/skills/<英小文字とハイフンの名前>/SKILL.md` を書く。案件に固有のもの（商品名、人物名）は差し替える所として `{ }` にする。
3. 書いたスキルをユーザーに見せ、名前と説明（いつ使うか）を確かめてから保存する。手元のリポジトリの決まり（コミットの仕方）に従う。

## 雛形
```markdown
---
name: <名前>
description: <何を作るスキルか。いつ使うか（ユーザーがどう言ったら使うか）を英語か日本語で1〜2文>
---

# <日本語の題>

## 使う場面
## 受け取るもの（{差し替える所} の一覧）
## 手順
1. 元になる画像: <モデル、設定、プロンプトの型>
2. 承認（ここで止める）
3. 動画: <モデル、設定、プロンプトの型>
4. 音: <台詞・曲・効果音の扱い>
5. 仕上げ・検品: <見る所>
## 迷う場面と決め方
- <場面>: <選ぶもの>（理由: <理由>）
## 費用の目安
- 1回 <n> クレジット（<日付> の get_cost）、通るまで約 <n> 回
## 失敗と対処
- <症状>: <直し方>
## 守ること
- 生成は見積もりと承認のあと。規則9b（実物と照合）、曲は生成しない、など手元の規則
```
