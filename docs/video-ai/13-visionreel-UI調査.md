## 4-1. UI 文言の提案

### A. 文言の決まり（出典つき）

出典から取った指針:
- ボタンとリンクには、ほぼ常に動詞を使う。凝った言い回しより明快さ。「Let's do it!」より「Send」✅（Apple HIG「Writing」 https://developer.apple.com/design/human-interface-guidelines/writing ）
- 共通の語の一覧を作り、それを見て言葉を揃える ✅（同上）
- 複数の画面にまたがる流れでは、始まり・次へ・終わりの言葉を決めて揃える（Get Started／Continue か Next／Done）✅（同上）
- 「私たち」を主語にしない。エラーは「〜を読み込めません」のように書く ✅（同上）
- 空の画面には、次にすることと、それを押すボタンを置く ✅（同上）
- 目立つボタンは1画面に1〜2個まで ✅（Apple HIG「Buttons」 https://developer.apple.com/design/human-interface-guidelines/buttons ）
- デジタル庁デザインシステム（DADS）のボタンの使い方 ✅（ https://design.digital.go.jp/dads/components/button/usage/ 、2026-10-21 更新）
  - 塗りのボタン（プライマリー）は原則1つまで。枠線のボタン（セカンダリー）は同じ文脈で原則3つまで
  - デスクトップでは「完了」「次へ」を右、「キャンセル」「戻る」を左に置く
  - ボタンを無効（disabled）にするのは避ける。押したときに、何をすべきかを示す。どうしても無効にするなら、近くに理由と有効にする方法を書く
  - DADS には、ボタンの文言（語尾など）の決まりは書かれていなかった
- ツールチップ（PatternFly https://www.patternfly.org/components/tooltip/design-guidelines 、GitLab https://design.gitlab.com/components/tooltip ）✅
  - 作業に欠かせない情報をツールチップに置かない
  - 画面にすでにある情報を繰り返さない。短く書く。1行を超えるもの、リンクやボタンを含むものはポップオーバーにする
  - 出るまでの遅れは、PatternFly が約300ms、GitLab が500ms
- マウスやフォーカスで出る補足（WCAG 2.2 の 1.4.13）✅（ https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html ）
  - 閉じられること（Esc など、ポインタを動かさずに閉じる）
  - 補足の上にポインタを移しても消えないこと
  - 引き金が外れるまで出続けること

VISIONREEL に当てはめた決まり（推測。出典の指針から組んだもの）:

| 決まり | 中身 |
|---|---|
| R1 ボタン | 対象があるときは「対象＋動詞」の短い句（「アニマティックを書き出す」）。一般の操作は2字の漢語（保存・承認・削除・複製・閉じる）。同じ操作はどの画面でも同じ語 |
| R2 括弧の補足 | 「（無料）」「（慣れている人向け）」「（1〜2分）」をボタンの文言から外す。費用・所要時間は札（バッジ）に、説明はツールチップに |
| R3 費用 | 費用がかかるボタンには金額の札を付ける（例: 「生成」＋「72 cr」）。費用がかからない見積もりは「0 cr」の札を付けるか、何も付けない |
| R4 記号 | ☺ ⌖ ▣ ⧉ ⊞ ⤢ のような文字の記号をやめ、1つのアイコンの組に揃える。アイコンだけのボタンには、読み上げ名とツールチップを付ける |
| R5 見出し | 名詞句にする。疑問形や説明文（「1カットに何本ずつ出すか」）をやめ、説明はツールチップに |
| R6 ラベル | 項目名だけにする。書き方の指示（「英語・カンマ区切り」）は入力欄の中の薄い例（プレースホルダ）か、ヘルプに移す |
| R7 状態 | 名詞か「〜中」「〜済み」に揃える。口語（「画はまだ」）をやめる |
| R8 流れの言葉 | 企画の段は「次へ」「戻る」、最後は「承認」。どの段でも同じ語にする |
| R9 用語 | 生成 AI の語（キーフレーム、リファレンス、アセット）と、日本の現場の語（コンテ、尺、テロップ）の使い分けを D の表で決め、それ以外の言い方をしない |

## 4-2. 使い勝手・機能のアイデア

優先順位は「効き目が大きく、手間が小さい」順。各項目に、対応する課題の番号を書く。

### 優先度 1（すぐやる価値が高い）

1. 承認の二度手間をなくす（U5）
- 実例: DADS は、ボタンを無効にせず、押したときに必要な作業を示すよう勧めている ✅（ https://design.digital.go.jp/dads/components/button/usage/ ）。Microsoft の人と AI の対話の指針 G16「操作の結果を伝える」✅（ https://www.microsoft.com/en-us/research/publication/guidelines-for-human-ai-interaction/ ）
- 当てはめ: 下調べの関門（P-SKILL／P-RESEARCH）を、承認のときではなく見積もりのときに判定し、承認待ちの札に「関門: 2件未了」と出す。札の中で関門の確認と承認を1回で済ませる（チェックを入れたら、そのまま「承認」が押せる）
- 効き目 大／手間 小〜中

2. 写真の選択をサムネイルの一覧にする（U2）
- 実例: Lightroom の比較表示（2枚を並べる）と選別表示（複数を並べる）。どちらでも採用・不採用の旗を付けられる ✅（ https://helpx.adobe.com/lightroom/help/browse-compare-photos.html ）
- 当てはめ:
  - ファイル名の一覧をサムネイルのグリッドにする
  - 種類（人物・場所・小道具・その他）と「案件の素材のみ」で絞り込む。アイコンやメニューバーの画像は既定で隠す（推測: 大きさや置き場で判定）
  - 選んだ画像は大きく表示する
- 効き目 大／手間 中

3. 右の欄を開閉できるインスペクタにする（U3）
- 実例: 編集ソフトのインスペクタは開閉できる（FCP のインスペクタ ❔ 手元の FCP で確かめる）
- 当てはめ: テイクの詳細は、選んだときだけ開き、閉じるボタンとキー（Esc）で閉じる。幅を変えられるようにする
- 効き目 中／手間 小

4. 時刻をその場の時刻で表示する（U11）
- 当てはめ: 保存は UTC のまま、表示は日本時間にする。ツールチップに UTC を出してもよい（推測）
- 効き目 小／手間 小

5. 読み上げ名に対象を入れる（U6）
- 実例: Apple HIG「Writing」はリンクに「ここをクリック」ではなく中身の分かる言葉を、と述べ、読み上げを使う人のためにとくに大事としている ✅
- 当てはめ: 「承認」ボタンの読み上げ名を「承認: 企画の工程（案件 SUNNY LEMON）」のようにする。案件・ジャンルの札も同じ
- 効き目 中／手間 小

6. 工程の承認の欠けを、要約と折りたたみにする（U7）
- 実例: GitLab は、1行を超える補足はツールチップでなくポップオーバーにするよう勧めている ✅（ https://design.gitlab.com/components/tooltip ）
- 当てはめ: 「C1〜C4 の欠け 12件（サイズ 5、カメラ 4、…）」と要約を1行出し、開くと一覧。欠けのある行から該当のカットへ飛べる
- 効き目 中／手間 小

### 優先度 2（効き目が大きい。手間は中）

7. テイクの選別を、たくさん並べて選ぶ形にする（F2、F3、O1）
- 実例:
  - Lightroom の選別表示（複数を並べて旗を付ける）✅
  - Final Cut Pro for iPad の評価（お気に入り＝緑、不採用＝赤の線。不採用を隠す表示）✅（ https://support.apple.com/guide/final-cut-pro-ipad/dev86aa28839/ipados ）
- 当てはめ:
  - テイクの画面に「グリッド」と「比較（2本）」の表示を足す
  - キー1つで採用・不採用（例: P／X。Lightroom のキーは ❔）
  - 「不採用を隠す」で残りを絞る
  - 本数の上限（8／16）は、生成の上限ではなく並べる上限として、ページ送りで数十本を並べられるようにする
- 効き目 大／手間 中

8. 不採用の理由を、次の版の直しに戻す（F3）
- 実例: 人と AI の対話の指針 G15「細かいフィードバックを促す」、G9「効率よく直せるようにする」✅（同上の論文）
- 当てはめ:
  - 不採用の理由を選択式のタグにする（手の崩れ、動きが止まる、カメラが勝手に動く、商品が違う、光が変わる、など）
  - 理由ごとに、直し方の候補を出す（`fixes-and-skeletons.md`、06 §6、07 の項目から）
  - 「この理由で版を改訂」で、プロンプトの版に「変更点」として1つだけ入れる（1回に1つを変える決まりと合う）
- 効き目 大／手間 中

9. 同じカットを2〜3モデルで作り比べる（F4）
- 実例: Frame.io は2つの版を並べて比べられると紹介されている ⚠️（ https://thedigitalprojectmanager.com/tools/frame-io-review/ ）。手元にはスキル `hf-model-compare` がある（11 §4-4）
- 当てはめ: モデルの判定の表で2〜3モデルにチェックを入れ、同じプロンプト・同じ参照・安い設定で一括で見積もる。できたら比較の表示で並べ、勝ったほうの設定で本番へ
- 効き目 大／手間 中

10. お金の見せ方（U5、F10）
- 実例:
  - Runway は、生成の費用がモデル・秒数・画質・本数で決まると説明し、残高を料金の画面で見せている ✅（ https://help.runwayml.com/hc/en-us/articles/15124877443219 ）
  - 実行の前に費用を見せる承認の札があるという利用者の報告 ⚠️（ https://marcandrews.com/runway-credits-explained/ ）
- 当てはめ（今の承認待ちを活かす）:
  - 生成のボタンに金額の札（R3）
  - 承認の札に「承認後の残高」と「この案件で使った合計／上限」を出す
  - 1日の終わりに、Higgsfield の使用履歴（`transactions`）と台帳を照らす（12 の V6）
- 効き目 中／手間 小〜中

11. Claude の提案の見せ方（F8）
- 実例:
  - 人と AI の対話の指針 G1「何ができるかを明らかにする」、G2「どのくらいうまくできるかを明らかにする」、G11「なぜそうしたかを明らかにする」、G8「すばやく退けられるようにする」✅（同上）
  - Notion の提案（相手が書いた変更を承認・却下し、受信箱でまとめて見る）✅（ https://www.notion.com/releases/2024-07-29 ）
- 当てはめ:
  - Claude が書いた項目に「未確認」の札と、根拠（出典の URL か、どの資料の何節か）を項目ごとに残す（G11）
  - 「採用」「却下」を項目ごとに押せるようにし、その履歴を残す
  - 却下したものは次の依頼に「却下した案」として渡す
- 効き目 大／手間 中

12. カット割りの尺の見せ方（U8）
- 実例:
  - Boords のアニマティックは、コマの印を Shift を押しながらドラッグして尺を直せる。均等に割り振るボタンもある。音を入れると全体の尺が音の長さになり、波形を見て合わせられる ✅（ https://help.boords.com/en/articles/1459425-boords-animatic-tool ）
  - StudioBinder のショットリストは、各ショットの準備と撮影の時間から合計を自動で出す ⚠️（宣伝のページ https://www.studiobinder.com/shot-list-creator/ ）
- 当てはめ:
  - カットの帯に「合計 14.0 秒／目標 15 秒（−1.0）」を常に出す
  - 帯の切れ目をドラッグして尺を直す（今の「この秒数にする」を置き換える）
  - ナレーションの波形を帯の下に出す
- 効き目 大／手間 中

13. アセット（登場するもの）の見せ方（U12）
- 実例:
  - LTX Studio の Elements は人物・場所・物・その他の4種類。プロンプトに @名前 で付ける。人物に声を結びつけられる。台本から自動で取り出して一覧で確かめる ⚠️（ https://ltx.studio/blog/getting-started-with-elements 、 https://ltx.studio/blog/ltx-storyboard-generator-update ）
  - Midjourney の Omni Reference（人物・物を参照画像から新しい絵に入れる）✅（ https://docs.midjourney.com/hc/en-us/articles/36285124473997 ）
- 当てはめ:
  - アセットの札に、子の資産（三面図・表情集・声）の状態を小さな札で並べる（「三面図 済」「声 未」）
  - カット設計の「登場するもの」の札にも同じ札を出す
  - 人物に声（ElevenLabs の声）を結びつける欄を足す
- 効き目 中／手間 中

14. 企画とカット設計の関係を見せる（U8、U9、O2）
- 実例:
  - LTX Studio は、台本をシーンとショットに分けたものを、生成の前にプレビューの欄で結合・分割・書き直しできる ⚠️（同上）
  - Apple HIG は、流れの始まり・次へ・終わりの言葉を揃えるよう勧めている ✅
- 当てはめ:
  - 企画の上に、工程の帯（企画 → 設計 → 静止画 → アニマティック → 生成 → 選別 → 書き出し）を常に出し、今いる所を強調する
  - 企画の「カット割り」の段の最後に、設計に写るカットの一覧（プレビュー）を見せてから「カット設計へ」
  - 進め方の型: 初めての案件は順に進む形（ウィザード）、2回目からは工程の帯から好きな所を開く形（作業台）。ホームで選べるようにする（推測）
- 効き目 大／手間 中

15. ホームの導線（U9、O2）
- 実例: Apple HIG は、空の画面に次にすることとボタンを置くよう勧めている ✅
- 当てはめ:
  - ホームの一番上に「続きから」（最後に開いた案件と、次の作業1つ）を置く
  - 案件が無いときは、「サンプルで試す（10分）」と「新規案件」の2つだけを大きく出す
  - ジャンル・サンプル・検査は下に折りたたむ
- 効き目 中／手間 小

16. 用語の解説の出し方（U13）
- 実例:
  - ツールチップは300〜500ms で出し、短く、作業に欠かせない情報は置かない ✅（PatternFly、GitLab）
  - 閉じられる・上に乗れる・出続けること ✅（WCAG 1.4.13）
- 当てはめ:
  - 解説の入切を右上（設定の奥ではなく、ヘルプの隣）に出す
  - 付ける語の基準: 生成 AI の語・略語・現場の専門語のうち、その画面で初めて出るもの1回だけ。ボタンには付けない（ボタンのツールチップは操作の説明用）
  - 出るまで 300〜500ms。Esc で閉じる
- 効き目 中／手間 小

17. アクセシビリティと見た目（U6、U10）
- 実例:
  - WCAG 2.2: 文字のコントラスト 4.5:1（1.4.3）、押す所の大きさ 24×24 CSS px 以上（2.5.8）❔（基準の番号と値は記憶。 https://www.w3.org/TR/WCAG22/ で確かめる）
  - Apple は押す所を 44×44 pt 以上にするよう勧めている ✅（Apple HIG「Buttons」）
- 当てはめ:
  - 記号をアイコンの組（Web 用の Lucide、Material Symbols など）に揃える
  - アイコンだけのボタンに読み上げ名を付ける
  - ダークモードでコントラストを測る（自動の検査に入れられる。推測）
- 効き目 中／手間 中

### 優先度 3（効き目は大きいが手間も大きい、または後でよい）

18. 完成素材のあと（U4、F7）
- 実例:
  - Frame.io の時刻つきコメント、版を重ねる管理、2つの版の比較、承認の段 ⚠️（ https://thedigitalprojectmanager.com/tools/frame-io-review/ ）
  - FCP の出力先（書き出しの定義済みの設定）✅（ https://support.apple.com/ja-jp/guide/final-cut-pro/verbeae235fe/mac ）
- 当てはめ:
  - 完成素材の各ファイルに「納品チェック」を付ける: 尺、解像度、フレームレート、ラウドネス（放送 −24 LKFS）、頭と尻の無音、AI 生成の開示の有無
  - 結果を納品物の一覧（PDF か Markdown）で書き出す
  - FCPXML の書き出し（12 の V7）
  - クライアント確認は、まずは時刻つきメモの書き出し（マーカー入りの FCPXML）から始める
- 効き目 大／手間 大

19. 効果音のコマ打ち（F6）
- 実例: Boords は、コマごとの音のメモを再生中に字幕のように出せる ✅（同上）
- 当てはめ: アニマティックのタイムラインに「効果音」の行を足し、時刻に効果音の名前を置く。その情報をプロンプトの効果音の欄と、MA のメモに書き出す
- 効き目 中／手間 中

20. 同時編集（F9）
- 当てはめ（推測）:
  - 盤面.json に版番号を持たせ、保存のときに版がずれていたら、上書きせずに差分を見せる
  - 企画で入れた「変えた項目だけ送る」形を、設計・音にも広げる
- 効き目 中／手間 中

21. 同一性を人が並べて見る（F5）
- 当てはめ:
  - 人物ごとに、全カットから顔のコマを1枚ずつ切り出して横に並べる「人物シート」を作る（ffmpeg、0クレジット。推測）
  - 三面図を左端に置き、比べやすくする
- 効き目 中／手間 中

22. 新しいモデルへの追随（F10、O4）
- 当てはめ: 判定の表を、`models_explore` の一覧と Artificial Analysis の順位（12 の V3）から更新する手順を、月1回の作業として課題に出す。表に無いモデルは「未知」ではなく「評価なし（値段のみ）」として候補に出す
- 効き目 中／手間 小

  - 終わった項目に印を付ける
- 効き目 中／手間 小

## 4-3. 作り手の手法で、まだ取り込めていないもの

画面にどう入れると使われるか（推測。手法の中身は手元の資料のとおり）。共通の考え方: 手法を「読む資料」にせず、入力欄の既定値・その場の注意・ワンクリックの型にする。

| 手法 | 画面への入れ方 | どこ |
|---|---|---|
| 効果の分解（Seedance 用の時系列） | ⑤ タイミングの欄を、0.0〜N 秒の行で書く表にする。各行に「動作」「カメラ」「効果」「音」。送るときに Seedance の時系列の書き方（00:00–00:02 …）に自動で組む | カット設計 ⑤ |
| 初版は速すぎる・動作弧3秒 | 動作の行が3秒より短いと「動きが速すぎる可能性」の注意を出す。初版の生成では、動作の秒を少し長めにする既定値 | カット設計 ⑤、直前検査 |
| 1ショット25〜35語の語数チェック | ⑦ プロンプトの欄の下に語数を常に出し、範囲を外れたら色を変える（止めない） | カット設計 ⑦ |
| フックの型16 | 企画の「構成」で CM・SNS のときに、冒頭2秒の型を16個のカードから選ぶ。選んだ型は1カット目の内容の下書きに入る | 企画（構成）、カット設計の1カット目 |
| 開示（AI 表示） | 企画の「媒体と納品仕様」に「AI 生成の開示」（YouTube の開示、EU 向けの配信の有無）の欄。納品チェックにも同じ項目（10 §5） | 企画、完成素材 |
| 字幕の帯 | 縦型の SNS 向けでは、カット設計の画面に字幕の安全域（下の帯）を重ねて見せる。テロップはコードで入れる前提 | カット設計（静止画の表示）、プレビュー |
| 広告は画像→3形式だけ動画 | 広告のときは「静止画を多く作る → 良いものだけ3形式（例: 縦・横・正方形）で動画にする」流れを、工程の既定にする。静止画の段で「動画にする」を選んだものだけが見積もりに進む | 企画（生成設定）、テイク |

このほか、12 の V5（Higgsfield の商品動画の公式の型18種）は、「広告フォーマット」と「カメラワーク」の選択肢に、動きの文ごと入れられる。
