根拠: ✅ 確かめた／ ⚠️ 動画の主張／ ❔ 未確認

## 0. 動画の仕組みと、Claude での置き換え

| 動画（ChatGPT） | Claude と Higgsfield | 備考 |
|---|---|---|
| ChatGPT に Higgsfield のプラグインを入れる | Claude（Claude Code、claude.ai、手元の VISIONREEL）に Higgsfield の MCP をつなぐ | すでにつながっている ✅ |
| GPT-6 Astra（複数の段の作業が得意）⚠️ | Claude ＋スキル（video-prompt、hf-* など） | 段取りはスキルに書いてある |

## 2. 「話していない間も動く」を Claude で行う

### 置き場の選び方

| 方法 | 向いていること | 気をつけること |
|---|---|---|
| A. Claude のクラウドの定期実行（このクラウドのセッションの「スケジュールされたタスク」） | 毎朝のネタ出し、台本とプロンプトの下書き、見積もり。Mac を閉じていても動く | 使えるコネクター（Higgsfield、Google Drive）を、作るときに指定する。Higgsfield が指定できるかは ❔（作るときに確かめる） |
| B. 手元の Mac で `claude -p` を launchd か cron で回す | VISIONREEL の承認待ちに直接置く。手元の素材と規則を使う | Mac が起きている必要がある。Claude のログインと環境変数に注意（VISIONREEL の運用の課題 O3 と同じ） |

### 守ること（動画の「料金を見せて」を仕組みにする）
- 定期実行では、生成（クレジットを使う操作）をしない。やるのは、調べる・案を出す・台本とプロンプトを書く・`get_cost` で見積もる、まで
- 結果は「承認待ち」として知らせる（手元は VISIONREEL の承認待ちに置く、クラウドは通知かファイル）。人が見て承認したら生成する
- 1回の実行で見積もる合計に上限を書いておく（例: 100 クレジット）
- Google Drive の「新商品フォルダ」は、ファイルが入った瞬間に動く仕組みではなく、定期実行のたびにフォルダを見て、前回からの新しいファイルだけを扱う

### 頼むときの3点（動画の Dots の頼み方と同じ）
1. 何を作るか
2. いつ、どのくらいの頻度で
3. どこで人に確かめるか（必ず「生成の前」）

例（そのまま使える）:
「毎朝7時に、AI 動画の最新の話題を調べて、ショート動画のネタを3つ出して。いちばん伸びそうな1本について、台本と、カットごとのプロンプト（video-prompt スキルの決まりで）を作り、`get_cost` で見積もって。生成はしないで、承認待ちとして知らせて。見積もりの合計は100クレジットまで。」

## 3. 確かめること（07 に足した D1〜D4）
| 番号 | 確かめること | 試し方 |
|---|---|---|
| D1 | クラウドの定期実行に Higgsfield の MCP を渡せるか。渡せたとき、生成せずに見積もりだけで止まるか | 生成なしの定期実行を1回 |
| D2 | `dubbing` の日本語→英語で、口合わせが自然か。`get_cost` が使えるか（道具に `get_cost` の欄が無い）| 5秒の台詞の動画1本 |
| D3 | 物の差し替え（`hf_mult_replace_object`）で、商品のラベルが実物どおりか（規則9b） | 4秒の広告1本と商品写真 |
| D4 | 承認の札の金額と、見積もりの金額が一致するか（動画では 108 と 288 で違った） | 1回の生成で、見積もりと `transactions` の実費を比べる |
