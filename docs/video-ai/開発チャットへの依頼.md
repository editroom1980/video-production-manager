# 開発のチャットへの依頼（2026-10-23 にまとめたもの）

クラウドのセッションで集めた資料（`docs/video-ai/`）とスキルを、VISIONREEL と手元の知識に反映するための依頼です。2026-10-22 に送った分のあとに出たもの（34項目）を、重なりをまとめて4つに分けました。

## 進め方の決まり
- 生成（クレジットを使う操作）はしない。生成が要るものは、`get_cost` で見積もって承認待ちに置くところまで。撃つのは依頼者の承認のあと。
- `git add -A` は使わない。変えたフォルダやファイルを名前で指定してコミットする。
- 手元の規則と資料が食い違うときは、手元の規則を優先する。規則を増やすときは6問の関門を通す。流行りを規則にしない。
- 「検討する」と書いた項目は、作るかどうかを先に決める。作るなら小さく作る。止める（先に進めない）作りにはせず、注意を出す作りにする。
- 終わったら、やったこと・やらなかったことと、その理由を短く一覧にする。

## B. 点検（確かめて、違っていれば直す）
上から順に。

B1. 企画で足した項目のうち、空だと先に進めない（止）ものがないか。小さな仕事が重くならないよう、「注」か空欄で進める形にする。
B2. 広告の形式の注意のうち、法律に触れるもの（景品表示法・薬機法・比較広告）が、法的な判断に見えない書き方（「確認を勧める」程度）になっているか。
B3. -24.0 LKFS の注意が、媒体がテレビのときだけ出るか。
B4. `検査/評価/evals.json` の「日本語ナレーションを生成しようとする」の項が、規則9c の改訂（生成してよい）に合っているか。
B5. MiniMax H3 で、開始の画像と参照を同時に渡す組み合わせ（422 になる）を止める処理があるか。
B6. 否定形の扱い（まず肯定の言い方で書き、直らないものだけ禁じる。01 §2 の5、06 §6）が、手元の規則と食い違わないか。
B7. 新しいスキル8つ（hf-*、workflow-to-skill）が、VISIONREEL の MCP の道具（承認待ちに置く `visionreel_request_generation` など）を正しく呼べるか。道具の名前や引数が違えば、スキルの文面を手元の名前に合わせて直す。
B8. 手元の既存のスキル（kaiwa-scene、katana-remix、effects-breakdown、ugc-ad-campaign、code-motion、cm-copy-ja）と、新しいスキルの役割が重なる所。重なっていれば片方に寄せる。hf-motion と code-motion、hf-partial-fix の ffmpeg の切り出しと VISIONREEL の道具（`ページを書き出す.py`、検品）も、重ならないように整理する。
B9. VISIONREEL のモデルの一覧と見積もりに `kling4_0`（3〜30秒、720p／1080p、21:9 あり）があるか。無ければ足す。値段は変わるかもしれないので、固定の値を持たずに `get_cost` で引く。
B10. 生成物の名前の付け方（hf-batch の `{案件}_{カット番号}_{モデル}_{秒数}s_t{テイク}.mp4`）が、VISIONREEL の今の決まりと食い違わないか。食い違えば、VISIONREEL の決まりに合わせて hf-batch を直す。
B11. 自動で回す流れ（Katana の自動起動、`claude -p`）で、止まった場所と理由を記録して見せる作りになっているか。

## C. 機能の検討
作るかどうかを決める。決めた理由も一覧に書く。

企画の段
- C1. 作る前に聞く項目（11 §0 の5: 伝えること、尺、縦横、本数とカット数、テンポ、素材と権利、参考の動画、予算）が揃っているか。足りなければ足す。
- C2. 広告の形式に、09 のジャンル（POV、構造分解、モーショングラフィックス、アプリ広告、MV 風、ゆるキャラのご当地 PR）のうち無いものを足す。それぞれの注意は次のとおり。確認の段に出す。
  - POV: 最初と最後の画像と、目線の高さ
  - 構造分解: 部品の数と順番
  - モーショングラフィックス: 文字なしで作り、色は3色
  - MV 風: 曲を先に決めて音声の参照へ
  - ゆるキャラ: 設定を1枚の元になる画像に揃え、動きを擬音のように書く
- C3. MV の項目に「コンセプト」「物語」を足す（前回足した3項目と合わせて5つ）。
- C4. 確認の段に「お客様と AI をどこまで使うか合意したか」と、「AI 生成の開示をどうするか（YouTube・EU 向けの配信の有無）」を足す。

カット設計の段
- C5. 元になる画像の段階で承認してから動画にする関門。
- C6. 前のカットから続けるときの注意。
  - つなぐ位置を「動きの途中」にする。
  - 人物を揃えるため、前のカットの最後のコマを次の開始の画像にする（ffmpeg で書き出す → アップロード → start_image）。これを VISIONREEL の道具で行えるようにする。MiniMax H3 では使わない。
- C7. 1カットに主な動作が2つ以上あるときに、注意を出す。
- C8. 特定の作品・作家の名前を挙げた「〇〇風」の書き方に、直前検査で注意を出す。
- C9. 人や動物が動くカットに、重心・重さの一文を足す。07 の U1 で効くと分かってから。

台詞と音の段
- C10. 会話シーンで「誰が何秒に何を言うか」の秒割りが無いときに、注意を出す。
- C11. 尺に対する台詞の文字数の注意。上限の数値は 07 の G4 で測ってから決める。
- C12. 一度作った声を使い回す運用（同じ声を音声の参照として渡す）を、会話シーンとナレーションの手順に明記する。
- C13. 音が主役のカット（ホラーなど）で、無音を含む音の演出を秒単位で書く欄。効果音を映像と別に作る流れ。

検品と記録
- C14. 完成した動画から十数コマを切り出して並べる確認（ffmpeg、0クレジット）を、検品に足す。
  - 10 §3 のチェックリストで見る（顔・体／文字・ロゴ／商品・建物／動き／光／音／表示・権利）。
  - 切り出したコマを AI にも見させる。
  - 今ある自動検品（尺・明滅・凍結・音）を補うもの。
- C15. 仮つなぎの書き出しで、音量（LKFS）を測って表示する（0クレジット）。
- C16. ジャンルごとに「うまくいった手順」を残す置き場（09 の N3、workflow-to-skill の保存先）。最初の数本は人が見て、迷った所と選んだものを書き足してからスキルにする運用を、手順書に足す。
