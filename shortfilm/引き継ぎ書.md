## 2. これは何か

**キネコマ**は、短編映画の撮影現場で使う、ブラウザのアプリです。iPhone のホーム画面に置いて、アプリのように使います。名前は「キネマ」と「コマ（フィルムの1コマ）」から。以前の名前は「撮影帳」で、保存の鍵の名前（`satsueicho`）に残っています。

- 台本・香盤表・カット表などの資料（テキスト・Word・Excel・CSV・PDF）を読み込み、シーン・出演・撮影日・カットを読み取ります。
- 撮影の日は、シーンごとに準備を確かめます。カチンコの画面で、テイク（判定・尺・ファイル名など）を記録します。
- 撮影のあと、スクリプトシートを PDF にして、監督にメールや AirDrop で送れます。
- 電波がなくても動きます（部品・書体を同梱し、先読みで残す）。
- データはその端末の中だけに保存されます（localStorage と IndexedDB）。

### 開き方

- アプリ：<https://editroom1980.github.io/video-production-manager/shortfilm/>
- 作品を開くリンク：`https://editroom1980.github.io/video-production-manager/shortfilm/#open=minatogawa&k=（鍵）`
  - 鍵は、このチャットで利用者に渡したリンクの `k=` の後ろです。**この文書にもリポジトリにも書きません**。鍵が分からないときは、利用者にリンクを貼ってもらってください。
  - ホーム画面のアプリは Safari と保存場所が別です。アイコンから開いたら、「資料」タブの「作品を開く」にリンクを貼って「開く」を押します。
- iPhone でアイコンや名前を変えたときは、ホーム画面のアイコンを消して、Safari の「共有」→「ホーム画面に追加」で登録し直します。記録が消えないよう、先に「出力」→「設定」の「作品データを保存」で控えを取ります。

## 4. 作品データ（鍵つき）の扱い

### 形式
- `'STK1'`（4バイト）＋ソルト16バイト＋IV12バイト＋暗号文（AES-256-GCM。最後の16バイトが認証タグ）
- 鍵からの導出：PBKDF2-SHA256・20万回・32バイト。アプリの `decryptWork` と、`tools/enc.js`・`tools/dec.js` は同じ方式です。

### 中身を直して出し直す手順
1. 鍵を外す：`node tools/dec.js works/minatogawa.bin tools/local/work.json 鍵`（`tools/local/` は `.gitignore` 済み）
2. `tools/local/work.json` を直します。`rev` を一つ上げ、`revNote` に何を変えたかを短く書きます。
3. 鍵をかける：`node tools/enc.js tools/local/work.json works/minatogawa.bin 鍵`
4. `works/index.json` の `rev` と `note` を同じに直します。
5. 送ると、利用者の iPhone に「資料が新しくなりました。ここをタップで更新（記録はそのまま）」が出ます。テイクやチェックの記録は残したまま、資料だけ入れ替わります（`mergeProject`）。

## 6. アプリの中身（画面ごと）

下に5つのタブがあります。

### 資料
- 作品が入っていないとき：作品を開くリンクを貼る欄。
- 「資料を見る」：撮影資料（1冊）・香盤表・チェックシート・編集素材リスト・スクリプトシート・撮り方の手引き。
- 資料の版：この端末の版と最新の版。「資料を最新に」と「アプリを最新に」（記録は消えない）。
- 「資料を入れ直す・足す」（作品が入っているときはたたむ）。読み取った結果を確かめてから取り込みます。

### 香盤
- 台本の順・撮影日ごと（↑↓で入れ替え）・人物（出番の表）。シーンを押すと詳細（台本・カット割り・カメラ案の書き直し・参考画像）。

### 撮影
- 撮影日のカード（コールシート風）：日付・集合時刻と場所、メモ、「現場の注意・カメラの決まりごと」（たたむ）、撮了の数・OK が無いカット・テイク数、進み具合（フィルムのコマ）、「次：S#… を記録する」。
- シーンのカード：時刻・S#・場所・ロケ地・内容・演出・参考画像・出演・小道具・衣装・メイク（押すと準備済み）・備考・繋がり・撮るもの（1カット1行）。カメラ案・図・理由・根拠・軸・前後は「カメラワーク（案・図・理由）」にたたんであります（開け閉めを覚える）。次に撮るシーンは、左端に「次に撮る」の印。

### 記録の画面（シーンの「記録する」）
- 上に C1・C2…（横1列）と「一連」「＋」。
- カチンコ：作品名・監督・日付、シーン・カット・テイク（「−」「＋」と数字で直せる）、カメラのファイル名（A カメ）、B カメのファイル名、音声のファイル名、タイムコード（数字だけで「:」が入る）。ファイル名は前のテイクの番号を一つ進めて先に入れます（FX6 の名前は C の後ろの番号を進め、後ろの日付は進めない）。
- タイマー（スタート→カット、録画中は赤い点）と OK・KEEP・NG。押すと記録し、OK なら次のカットへ進みます。
- 押したあと6秒、知らせに「取り消す」（入れた内容は残す）。記録の画面を開いている間は、画面を自動で消さない（Wake Lock）。
- メモとメモの言葉、このカットの撮り方（案A〜C の切り替え、カメラ・レンズの mm・理由・根拠・図）、このシーンのテイク、繋がりメモ、編集への申し送り、台本。
- その日のシーンがすべて撮了になると、「撮影の終わり」で控えを残すよう知らせます（その日の PDF を送る・作品データを保存）。

### 記録
- テイクの一覧（台本の順・撮影の順、すべて・OK と KEEP だけ・撮り残し）。テイクを押すと直せます。
- 「スクリプトシートを PDF で監督に送る」。

### 出力
- スクリプトシート：撮影日・シーン（はじめは「撮ったシーンだけ」）・テイク・並び順を選び、「PDF で監督に送る」。ほかに画面で見る・表をコピー・Excel 用。
- ほかの資料を渡す：撮影チェックシート・撮影資料・編集素材リスト・香盤表を選んで、画面で見る・印刷・表をコピー・Excel 用・文字で送る。
- 設定：表示（暗い・明るい・端末に合わせる。はじめは暗い）、記録の画面の欄（音声・タイムコード・B カメ）、作品データ（保存・読み込む・リンクで開く・全部消す）。

### スクリプトシートの PDF
- 端末の中で、キャンバスに A4 横で描き、JPEG にして PDF に包みます（`scriptPdf`・`pdfBlob`）。文字は画像なので選べません。
- 見出し：上にフィルムの帯、タイトル・作品名・監督・出力日時、まとめの枠（作品・監督・撮影・記録・撮影日・テイク数・OK／KEEP／NG・OK の尺の合計）。
- シーンの帯（黒）→ 繋がり・編集へ → 表の見出し → カットの帯（内容・テイク数・使うテイク）→ テイクの行。OK のテイクは番号を丸で囲みます。B カメ・音声・タイムコードの列は、入っているときだけ出します。改ページしたら、シーンの帯（つづき）と表の見出しをもう一度出します。
- 送る：`navigator.share({ files })`（iPhone ではメール・AirDrop・LINE・ファイルに保存が選べる）。使えないときは保存（ダウンロード）。

### カメラ位置の図と撮り方の手引き
- `figSVG(stage, fig)`：上から見た図。カメラを置く側の色、軸（イマジナリーライン）、レンズの mm から写る範囲（2・atan(18/mm)）、人物と動きの矢印、高さ・サイズ・レンズの凡例。
- 撮り方の手引き：7分類・27の原則（何をする・なぜ・現場で確かめること・出典）。カメラ案の言葉と図から、当てはまる原則を重みの順に最大5つ選んで「根拠」として出します（`autoBasis`）。出典は本の目次・出版社の紹介・解説記事などで確かめたもの（原典の本文まで確かめていないものは注記）。衣笠監督の『映画制作の教科書』も出典の一つです。

## 9. 分かったこと・つまずいたこと（同じ失敗をしないために）

### iPhone（ホーム画面のアプリ）
- **ノッチ付近のぼやけ**：上の端の帯をグラデーションだけで塗ると、iOS がステータスバーの下をぼかします。上の帯は無地の色（`#111215`）にし、ページの地・上の帯・`theme-color` を同じ黒にそろえます。ぼやけの出ていない利用者の「キューシート」アプリ（リポジトリ `lepont-cue`）と同じ作りです（`viewport-fit=cover`、ステータスバーは `black`、ページの地と上の帯が同じ黒）。画面全体の箱は `position: fixed` で、無地の地の色を持たせています。
  - 利用者の別のアプリ `footpath-map` には、`viewport-fit=cover` をやめる直し方の記録もあります。このアプリでは一度その形にしましたが、キューシートと同じ形に戻して、ぼやけが直ったと利用者から確かめてもらいました。
  - 利用者の JOB HEROES のアプリも同じ症状とのこと。直すかどうかは返事待ちです。
- 先読み（`sw.js`）が古い画面を出し続けたことがあります。今はネットにつながるとき、`no-store` で必ずサーバーから取ります。公開のたびに `CACHE` を上げます。
- ホーム画面のアプリと Safari は、保存場所が別です。
- 共有（`navigator.share`）は、押したすぐあとでないと iPhone で断られることがあります。PDF は先に作っておき、「送る」を押したときに共有します。

### 資料の読み取り
- 縦書きの PDF は、隣の文字との距離で縦か横かを決め、列を組み立てて読みます。回転したページは、ビューポートの変換で直します。表は列の位置を投影でそろえます。
- 台本：柱（シーン見出し）の形、話者（字幕・タイトル・唄声・N などは台詞にしない）、「字　幕」のような空きのある話者名、折り返し、入れ子の『』、改ページの空白に気をつけています。

### テスト
- Playwright で日本語の名前のファイルを選ばせると失敗するので、英字の名前の写しを使います。
- `pkill` と同じコマンドの中で別のことをすると、シェルごと止まることがあります。分けて実行します。
- テスト用の名前の付いたファイルの保存（ダウンロード）は、このテストの道具では名前が `download` になります。アプリの不具合ではありません。

### 調べもの

## 10. 監督・脚本について（2026年11月4日の調査）

公開されている仕事の情報（経歴・作品・著書・報道）に絞って調べました。細かい年や長さは原典で確かめていません。

### 衣笠竜屯（きぬがさ りゅうとん）監督
- 神戸を拠点にする映像作家・映画監督。1965年生まれ。高校時代から映画を作り始めた。
- 1980年代にヨコハマ自主映画祭などに関わったのち、1989年に映画制作団体「神戸活動写真倶楽部 港館」を立ち上げ、今も主宰（報道では「30年間主宰」）。
- 時代劇の巨匠・衣笠貞之助とは別人。
- 主な監督作品：
  - 「インスタントのみそ汁」（1993年、1994年の第27回映像コンテストで姫路青年会議所理事長賞）
  - 「魔法世界」（1991年、90分）
  - 「草の時、風の場所」（2009年、14分、明石ケーブルテレビで放送）
  - 「RE:ありがとう」（2011年）
  - 「バニーカクタスは喋らない」（2012年、40分）
  - 「シナモンの最初の魔法」（2015年に興行上映）
  - 「クラブのジャック ～やすらぎの銃弾～」（2017年、上映企画「映画のロシアンルーレット」の1本、十三のシアターセブン。脚本・監督・録音・照明）
  - 「神戸 ～都市が囁く夢～」（短編版18分が2021年、長編版40分が2023年、劇場版77分が2025年）
- 著書：『映画制作の教科書 プロが教える60のコツ ～企画・撮影・編集・上映～』（メイツ出版、2020年。台湾版あり）、『映画脚本の教科書 プロが教えるシナリオのコツ』（同、2022年、監修）。
- 映像演技のワークショップを主宰。東京48時間映画祭（Tokyo 48HFP）にもワークショップとして参加。

### 川村正英（かわむら まさひで）さん
- 『湊川新開地の残像』の脚本・制作・記録、撮影の現場責任者。
- 「神戸 ～都市が囁く夢～」の脚本とプロデューサー。
  - 神戸と映画の150年を、「映画館の発展」という見方から描いた歴史フィクション（ドキュメンタリードラマ）。主人公の節子が映画館で不思議な作品を見るところから始まり、神戸大空襲・阪神淡路大震災・コロナ禍を通して街と映画の歩みをたどる。
  - 主演は mayu さん、ナレーションは西出明さん。
  - 上映：長編版を2023年10月にこうべまちづくり会館、劇場版を2025年1月16・17日に新開地のパルシネマしんこうえん（震災30年）、同じ年の6月10〜13日に元町映画館。
  - 報道では、「予期せぬことがあっても前向きに進もう」という思いを込めたと話している。
- ほかの経歴や作品は、公開された情報では見つからなかった。同じ名前で高知の整形外科医の方がいるが、別人。

## 11. テストの回し方

`shortfilm` フォルダで次を実行すると、鍵を外した作品データを `tools/local/` に用意し、確認用のサーバーを立てて、`tools/tests/` のテストをすべて流します。

```bash
bash tools/tests/run.sh 鍵
```

- 要るもの：node、python3、playwright。クラウドの環境には最初から入っています。
- **Mac など、playwright が入っていない手元の環境**では、先に一度だけ次を実行します（`tools/package.json` に版を決めてあります。部品は `tools/node_modules/` に入り、リポジトリには入りません）。
  ```bash
  cd tools && npm install && npx playwright install chromium && cd ..
  ```
- 手元の写し（クローン）が古いときは、`git fetch origin` のあと、`main` から新しい作業場所（ブランチや worktree）を切って作業します。ほかのチャットの書きかけが残っている写しには触らないでください。
- テスト：見本の作品（`sample`）、資料を画面で見る（`docs-view`）、資料の更新（`work-update`）、カメラ位置の図（`figs`）、記録とレンズ（`rec-lens`）、撮り方の手引き（`guide`）、PDF（`pdf`）、FX6 のファイル名（`fx6-name`）、たたみと出力（`fold-out`）、取り消し・画面を消さない・撮影の終わり（`undo-wake-dayend`）。
- 資料の読み取りのテストは、もとの資料（香盤表 `kouban.xlsx`・台本 `daihon.docx`）を `tools/local/files/` に置いたときだけ流れます。
- 図と文の食い違いの検査：`python3 tools/audit.py tools/local/work.json`（`-all` で全部の図を一覧）。残る3件は、分かっている誤検出です。
