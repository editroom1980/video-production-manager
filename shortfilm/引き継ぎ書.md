## 2. これは何か

**キネコマ**は、短編映画の撮影現場で使う、ブラウザのアプリです。iPhone のホーム画面に置いて、アプリのように使います。名前は「キネマ」と「コマ（フィルムの1コマ）」から。以前の名前は「撮影帳」で、保存の鍵の名前（`satsueicho`）に残っています。

- 台本・香盤表・カット表などの資料（テキスト・Word・Excel・CSV・PDF）を読み込み、シーン・出演・撮影日・カットを読み取ります。
- 撮影の日は、シーンごとに準備を確かめます。カチンコの画面で、テイク（判定・尺・ファイル名など）を記録します。
- 撮影のあと、スクリプトシートを PDF にして、監督にメールや AirDrop で送れます。
- 電波がなくても動きます（部品・書体を同梱し、先読みで残す）。
- データはその端末の中だけに保存されます（localStorage と IndexedDB）。

### 開き方

- アプリ：<https://editroom1980.github.io/video-production-manager/shortfilm/>
- 作品を開くリンク：`https://editroom1980.github.io/video-production-manager/shortfilm/#open=minatogawa&k=（鍵）`
  - 鍵は、利用者が持っている「作品を開くリンク」の `k=` の後ろです。**この文書にもリポジトリにも書きません**。受け取り方は0章の3。
  - ホーム画面のアプリは Safari と保存場所が別です。アイコンから開いたら、「資料」タブの「作品を開く」にリンクを貼って「開く」を押します。
- iPhone でアイコンや名前を変えたときは、ホーム画面のアイコンを消して、Safari の「共有」→「ホーム画面に追加」で登録し直します。記録が消えないよう、先に「出力」→「設定」の「作品データを保存」で控えを取ります。

## 4. 作品データ（鍵つき）の扱い

### 形式
- `'STK1'`（4バイト）＋ソルト16バイト＋IV12バイト＋暗号文（AES-256-GCM。最後の16バイトが認証タグ）
- 鍵からの導出：PBKDF2-SHA256・20万回・32バイト。アプリの `decryptWork` と、`tools/enc.js`・`tools/dec.js` は同じ方式です。

### 中身を直して出し直す手順
1. 鍵を外す：`node tools/dec.js works/minatogawa.bin tools/local/work.json 鍵`（`tools/local/` は `.gitignore` 済み）
2. `tools/local/work.json` を直します。`rev` を一つ上げ、`revNote` に何を変えたかを短く書きます。
3. 鍵をかける：`node tools/enc.js tools/local/work.json works/minatogawa.bin 鍵`
4. `works/index.json` の `rev` と `note` を同じに直します。
5. 送ると、利用者の iPhone に「資料が新しくなりました。ここをタップで更新（記録はそのまま）」が出ます。テイクやチェックの記録は残したまま、資料だけ入れ替わります（`mergeProject`）。

## 6. アプリの中身（画面ごと）

下に5つのタブがあります。

### 資料
- 作品が入っていないとき：作品を開くリンクを貼る欄。
- 「資料を見る」：撮影資料（1冊）・香盤表・チェックシート・編集素材リスト・スクリプトシート・撮り方の手引き。
- 資料の版：この端末の版と最新の版。「資料を最新に」と「アプリを最新に」（記録は消えない）。
- 「資料を入れ直す・足す」（作品が入っているときはたたむ）。読み取った結果を確かめてから取り込みます。

### 香盤
- 台本の順・撮影日ごと（↑↓で入れ替え）・人物（出番の表）。シーンを押すと詳細（台本・カット割り・カメラ案の書き直し・参考画像）。

### 撮影
- 撮影日のカード（コールシート風）：日付・集合時刻と場所、メモ、「現場の注意・カメラの決まりごと」（たたむ）、撮了の数・OK が無いカット・テイク数、進み具合（フィルムのコマ）、「次：S#… を記録する」。
- シーンのカード：時刻・S#・場所・ロケ地・内容・演出・参考画像・出演・小道具・衣装・メイク（押すと準備済み）・備考・繋がり・撮るもの（1カット1行）。カメラ案・図・理由・根拠・軸・前後は「カメラワーク（案・図・理由）」にたたんであります（開け閉めを覚える）。次に撮るシーンは、左端に「次に撮る」の印。

### 記録の画面（シーンの「記録する」）
- 上に C1・C2…（横1列）と「一連」「＋」。
- カチンコ：作品名・監督・日付、シーン・カット・テイク（「−」「＋」と数字で直せる）、カメラのファイル名（A カメ）、B カメのファイル名、音声のファイル名、タイムコード（数字だけで「:」が入る）。ファイル名は前のテイクの番号を一つ進めて先に入れます（FX6 の名前は C の後ろの番号を進め、後ろの日付は進めない）。
- タイマー（スタート→カット、録画中は赤い点）と OK・KEEP・NG。押すと記録し、OK なら次のカットへ進みます。
- 押したあと6秒、知らせに「取り消す」（入れた内容は残す）。記録の画面を開いている間は、画面を自動で消さない（Wake Lock）。
- メモとメモの言葉、このカットの撮り方（案A〜C の切り替え、カメラ・レンズの mm・理由・根拠・図）、このシーンのテイク、繋がりメモ、編集への申し送り、台本。
- その日のシーンがすべて撮了になると、「撮影の終わり」で控えを残すよう知らせます（その日の PDF を送る・作品データを保存）。

### 記録
- テイクの一覧（台本の順・撮影の順、すべて・OK と KEEP だけ・撮り残し）。テイクを押すと直せます。
- 「スクリプトシートを PDF で監督に送る」。

### 出力
- スクリプトシート：撮影日・シーン（はじめは「撮ったシーンだけ」）・テイク・並び順を選び、「PDF で監督に送る」。ほかに画面で見る・表をコピー・Excel 用。
- ほかの資料を渡す：撮影チェックシート・撮影資料・編集素材リスト・香盤表を選んで、画面で見る・印刷・表をコピー・Excel 用・文字で送る。
- 設定：表示（暗い・明るい・端末に合わせる。はじめは暗い）、記録の画面の欄（音声・タイムコード・B カメ）、作品データ（保存・読み込む・リンクで開く・全部消す）。

### スクリプトシートの PDF
- 端末の中で、キャンバスに A4 横で描き、JPEG にして PDF に包みます（`scriptPdf`・`pdfBlob`）。文字は画像なので選べません。
- 見出し：上にフィルムの帯、タイトル・作品名・監督・出力日時、まとめの枠（作品・監督・撮影・記録・撮影日・テイク数・OK／KEEP／NG・OK の尺の合計）。
- シーンの帯（黒）→ 繋がり・編集へ → 表の見出し → カットの帯（内容・テイク数・使うテイク）→ テイクの行。OK のテイクは番号を丸で囲みます。B カメ・音声・タイムコードの列は、入っているときだけ出します。改ページしたら、シーンの帯（つづき）と表の見出しをもう一度出します。
- 送る：`navigator.share({ files })`（iPhone ではメール・AirDrop・LINE・ファイルに保存が選べる）。使えないときは保存（ダウンロード）。

### カメラ位置の図と撮り方の手引き
- `figSVG(stage, fig)`：上から見た図。カメラを置く側の色、軸（イマジナリーライン）、レンズの mm から写る範囲（2・atan(18/mm)）、人物と動きの矢印、高さ・サイズ・レンズの凡例。
- 撮り方の手引き：7分類・27の原則（何をする・なぜ・現場で確かめること・出典）。カメラ案の言葉と図から、当てはまる原則を重みの順に最大5つ選んで「根拠」として出します（`autoBasis`）。出典は本の目次・出版社の紹介・解説記事などで確かめたもの（原典の本文まで確かめていないものは注記）。衣笠監督の『映画制作の教科書』も出典の一つです。

## 8. これまでの依頼と対応（順番どおり）

1. 短編映画の香盤表・台本・資料から、撮影チェックシートと編集に渡すスクリプト表を出す HTML アプリを作れ → 「撮影帳」を作った。
2. ドライブの「湊川新開地の残像」の中身を全部読んで落とし込め → 縦書きの台本 PDF、回転した香盤表 PDF などを読み取れるようにし、作品データにした。最初はリモートの共有フォルダがつながらず、Google ドライブ経由にした。
3. JOB HEROES SHISO のときのように、ブラウザで普通に開けるアプリにしろ → GitHub Pages とホーム画面のアプリにした。
4. 中華フォントをどうにかしろ → 日本語の書体（Noto Sans JP）にした。PDF は要らないから全部アプリで見られるようにしろ → 資料を画面の中で見られるようにした。
5. ホーム画面に追加したらファイルを選べとなった → 鍵つきリンクで、ファイルなしで作品を開けるようにした。
6. シーンごとに効果的なカメラワークを、前後のつながりとイマジナリーラインを踏まえ、理由つきで → カメラワーク案。別案もすぐ出せるように → 案B・案C。

## 9. 分かったこと・つまずいたこと（同じ失敗をしないために）

### iPhone（ホーム画面のアプリ）
- **ノッチ付近のぼやけ**：上の端の帯をグラデーションだけで塗ると、iOS がステータスバーの下をぼかします。上の帯は無地の色（`#111215`）にし、ページの地・上の帯・`theme-color` を同じ黒にそろえます。ぼやけの出ていない利用者の「キューシート」アプリ（リポジトリ `lepont-cue`）と同じ作りです（`viewport-fit=cover`、ステータスバーは `black`、ページの地と上の帯が同じ黒）。画面全体の箱は `position: fixed` で、無地の地の色を持たせています。
  - 利用者の別のアプリ `footpath-map` には、`viewport-fit=cover` をやめる直し方の記録もあります。このアプリでは一度その形にしましたが、キューシートと同じ形に戻して、ぼやけが直ったと利用者から確かめてもらいました。
  - 利用者の JOB HEROES のアプリも同じ症状とのこと。直すかどうかは返事待ちです。
- 先読み（`sw.js`）が古い画面を出し続けたことがあります。今はネットにつながるとき、`no-store` で必ずサーバーから取ります。公開のたびに `CACHE` を上げます。
- ホーム画面のアプリと Safari は、保存場所が別です。
- 共有（`navigator.share`）は、押したすぐあとでないと iPhone で断られることがあります。PDF は先に作っておき、「送る」を押したときに共有します。

### 資料の読み取り
- 縦書きの PDF は、隣の文字との距離で縦か横かを決め、列を組み立てて読みます。回転したページは、ビューポートの変換で直します。表は列の位置を投影でそろえます。
- 台本：柱（シーン見出し）の形、話者（字幕・タイトル・唄声・N などは台詞にしない）、「字　幕」のような空きのある話者名、折り返し、入れ子の『』、改ページの空白に気をつけています。

## 11. テストの回し方

`shortfilm` フォルダで次を実行すると、鍵を外した作品データを `tools/local/` に用意し、確認用のサーバーを立てて、`tools/tests/` のテストをすべて流します。

```bash
bash tools/tests/run.sh 鍵
```

- 要るもの：node、python3、playwright。クラウドの環境には最初から入っています。
- **Mac など、playwright が入っていない手元の環境**では、先に一度だけ次を実行します（`tools/package.json` に版を決めてあります。部品は `tools/node_modules/` に入り、リポジトリには入りません）。
  ```bash
  cd tools && npm install && npx playwright install chromium && cd ..
  ```
- 手元の写し（クローン）が古いときは、`git fetch origin` のあと、`main` から新しい作業場所（ブランチや worktree）を切って作業します。ほかのチャットの書きかけが残っている写しには触らないでください。
- テスト：見本の作品（`sample`）、資料を画面で見る（`docs-view`）、資料の更新（`work-update`）、カメラ位置の図（`figs`）、記録とレンズ（`rec-lens`）、撮り方の手引き（`guide`）、PDF（`pdf`）、FX6 のファイル名（`fx6-name`）、たたみと出力（`fold-out`）、取り消し・画面を消さない・撮影の終わり（`undo-wake-dayend`）。
- 資料の読み取りのテストは、もとの資料（香盤表 `kouban.xlsx`・台本 `daihon.docx`）を `tools/local/files/` に置いたときだけ流れます。
- 図と文の食い違いの検査：`python3 tools/audit.py tools/local/work.json`（`-all` で全部の図を一覧）。残る3件は、分かっている誤検出です。

## 13. 2026年11月5日に足したこと（3.6・第7版）

### 依頼
1. ジンバルを使った移動撮影（一脚と組んでクレーンのように使うなど）を撮り方に足せるか。今回のシーンで効果が出そうなところはあるか。
2. カメラ・レンズ・フィルターなどを登録し、シーンに合う組み合わせを出せるようにしたい。
3. 撮影の当日（11月5日 13時から）の前に作り替えてよい、との返事。機材の一覧は利用者から受け取った。

### したこと
- **撮り方の手引き**（`GUIDE`・`SRC`）：「カメラの動きと固定」に、ジンバル・一脚の6項目（ついていく・前を行く／横に並んで動く／寄っていく・離れていく／回り込む／一脚と組んで上下に動く／低い位置の移動）を足した。「レンズ」に、ND とシャッターの1項目を足した。出典は販売店や映像の教室の解説記事で、項目ごとに注記してある。
- **根拠の付け方**（`autoBasis`）：移動の道すじ（`fig.campath`）があると、いつも「手持ち」を付けていた。文か `fig.sup` に「ジンバル」「一脚」があるときは付けない。
- **機材の登録**（出力 → 設定 → 機材、`SHEET.kit`）：カメラ（センサー・内蔵 ND・重さ）、レンズ（焦点距離・F 値・フィルター径・重さ）、フィルター（種類・強さ・付く径。アダプターリングで付く範囲「67〜82」も書ける）、支え（三脚・一脚・ジンバルと積める重さ・スライダー・ドローン）。レンズは名前に「24-70mm F2.8」とあれば、空いている焦点距離と F 値を埋める。
- **保存**：機材は作品とは別に `localStorage` の `satsueicho.v1.kit` に置く（`KIT`）。資料の更新・作品の入れ替え・全部消すでは消えない。作品データや控えの JSON に `kit` があれば、まだ無い名前だけを足す（`kitAdopt`）。一度足して利用者が消したものは、`KIT.seen` に覚えて足し直さない。控えの保存（`backup`）には `kit` を入れる。
- **カットごとの組み合わせ**（`kitPlan`・`kitHtml`）：記録の画面の「このカットの撮り方」と、撮影タブのカメラワークに、選んでいる案に合わせて理由つきで出す。
  - カメラ：選んだもの。選んでいなければ1台目。ジンバルの案では、重さの分かっている中で軽いものを選ぶ。
  - レンズ：案の換算 mm をセンサーの倍率で割り、その mm を含むズームか、いちばん近い単焦点を選ぶ。夜・地下・屋内は F 値の小さいものを先に。内蔵 ND の無いカメラの明るい屋外では、ND フィルターが付くレンズを先に。
  - ND：夜・地下・屋内は外す。それ以外は内蔵 ND → 可変 ND → 固定 ND の順。フィルターの径がレンズに合わなければ知らせる。
  - PL：カットの文に反射の言葉（水面・流れる水・ガラス・映り込みなど）があるときだけ。場所の名前は見ない（「菊水座」の「水」に反応したため）。
  - ミスト：古写真・ＣＧと重ねる実景（手引きの `vfx` の言葉）では外す。
  - 支え：ジンバル・一脚の案はジンバル（積める重さを超えたら知らせる）、手持ちの案は手持ち、それ以外は三脚。文に「ドローン」「空撮」があるときだけドローン（航空法の許可・承認の注意を出す）。
- **記録**：テイクに `kit`（組み合わせの1行）を残す。テイクの画面で直せる。スクリプトシートの画面（メモの欄）・CSV（「機材」の列）・文字・PDF（メモの欄の頭）に出す。
- **3.8（利用者の指示「よく使う24-70にミストを付けて優先して使うべき。いちいち付け替えるのは手間。交換は24mm以下を使うときだけ。それでも G マスターを使う理由があれば使う。設定はどこでするか教えろ」）**：レンズの選び方を「基本のレンズ（付けたまま）」の考え方に変えた。基本のレンズで撮れる mm（長い側は25%寄れば届く所まで。24-70 なら24〜87mm）は付け替えない。交換を出すのは、広すぎるとき・長すぎるとき・ジンバルに載らないとき（重さの分かる軽いレンズへ）だけで、「交換：」と理由を出す。夜・地下・屋内では、F 値で1段以上明るいレンズがあれば「替える手もある」と段数つきで添えるだけで、自動では替えない。設定は、出力 → 設定 → 機材 の画面のいちばん上の「いつもの組み方」：基本のレンズ（選ぶ欄）・優先のカメラ（選ぶ欄）・いつも付けるフィルター（ミスト・PL のチップ）。各機材の下の「優先して使う」は外した（いつもの組み方に集めた）。撮影タブのシーンのカードの「カメラワーク」の見出しに、レンズ交換のあるカットを出す。
- **3.7・第9版（利用者の指示「レンズは24-70を優先、今回の撮影はミストを付ける。その優先をアプリで設定できるように」）**：登録の画面で、機材ごとに「優先して使う」（ミストと PL は「いつも付ける」）を付け外しできるようにした（`pri` が `'on'`／`'off'`。外したときに `'off'` を残すので、資料の更新の「空いている欄を埋める」で戻らない）。優先のカメラ・三脚などは同じ種類の中で先に選ぶ。優先のレンズは、案の mm から25%ほど離れていても先に選ぶ（85mm の案は24-70 の70mm、100mm・135mm の別案7つだけ TAMRON 50-400）。いつも付けるミスト・PL は、古写真・ＣＧと重ねる実景にも付け、「重ねにくいときは、このカットだけ外す」と添える。付けるフィルターが付かない径のレンズは後回し。第9版で SIGMA 24-70mm とブラックミスト 1/8 を優先にした。
- **3.6.1・第8版**：資料の更新（`mergeProject`）で、前に作品データから入った機材は、空いている欄だけを埋めるようにした（この端末で書いた値は上書きしない）。2本とも旧型と聞いたので、24-70mm の重さ 835g を入れた第8版を出した。
- **作品データ第7版**：S#4 C1（東側を並んで歩く）・C3（主観の歩きをジンバルで）、S#9 C2（後ろについて降りる）、S#10 C4（一脚で足元から持ち上げる）に案D を足した（`alts` に `gim: true` の印）。決まりごとの「小型カメラ1台と三脚1台」の行を、案D を使える条件と「重ねる実景は三脚で固定」に直した。安全の決まりごとに、ジンバルを一脚で上げる・後ろについて歩くときの注意を足した。利用者の機材を `kit` に入れた。
- **テスト**：`tools/tests/kit.js` を足した（登録・自動入力・組み合わせ・重さと径の知らせ・テイクと CSV・資料の更新と全部消すで消えないこと・作品データの機材が入ること）。アプリの中を読むため、確認用のサーバー（`localhost`）で開いたときだけ `window.__kinekoma` を作る。

### 登録した機材（第7版の `kit`）

### したこと
- **技術の手引き**（`TECH_CATS`・`TECH`・`SHEET.tech`）：撮り方の手引きとは別に、8分類29項目。フレームレートの選び方・シャッター180度・照明のちらつきと電源の周波数・スロー／露出（ゼブラ・波形）・S-Log3 の露出の目安・ベース ISO と EI・ND の段数／ホワイトバランス・ルック・LUT／ピント・手ぶれ補正・ブリージング・S35／記録の方式・カード・記録時間・控え（3-2-1）・ファイル名／録音レベル・マイクの入力・S&Q で音が入らない・別の録音機／タイムコード・複数のカメラの同期／熱と結露・ドローン（航空法）・道路使用許可。項目の形は撮り方の手引きと同じ（何をする・なぜ・現場で確かめる・出典）で、表（`tbl`）を持てる。
- **カメラの説明書から**（`MANUALS`・`SHEET.man`）：FX6 は19行、FX3 は13行。各行にページ番号。機材の画面で、カメラの名前に「FX6」「FX3」が入っていると「説明書の要点を見る」が出る（`manualFor`）。
- **計算**：シャッター（フレームレートと電源の周波数から、昼の 180° と、照明の下でちらつかない速さ）、記録できる時間（Mbps と GB）、ND の段数、換算の mm。
- **ちらつかないシャッター**（`shutFlicker`）：照明は電源の周波数の2倍で明滅するので、露光時間を 1/(2×Hz) の整数倍にする。1コマの時間を超えないものの中で 180° にいちばん近いものを選び、長い側が近くても、3割以内に短い側があれば短い側（23.98p・60Hz は 1/40 ではなく 1/60）。119.88p・50Hz は合う速さが無い。
- **機材の画面の「いつもの組み方」**：フレームレート（`KIT.fps`。既定 23.976）と電源の周波数（`KIT.hz`。既定 60）を足した。カットごとの組み合わせ（`kitPlan`）に「シャッター」の行が出る：昼の屋外は 180°、夜・屋内・地下・照明や看板の写るカットはちらつかない速さ（カメラが FX6 なら Flicker Reduce の案内も）。カットの文に「スロー」があれば「スロー」の行（119.88fps・倍率・音が入らない注意）。ND の行の説明も、決めたフレームレートのシャッターで書く。
- **入口**：資料の画面の「技術の手引き」、撮影の画面の「現場の注意・カメラの決まりごと」の中、機材の根拠のボタン（`PRIN_BY` で撮り方と技術の両方を引く）、使い方の画面。
- **テスト**：`tools/tests/tech.js` を足した（ちらつきの表と計算の一致・出典の抜け・さがす・計算・機材の画面・説明書の要点・カットごとのシャッター・保存）。`window.__kinekoma` に `TECH`・`MANUALS`・`SRC`・`shutFlicker`・`shutLabel`・`shutAngle` を足した。

### 3.9.1（利用者の指示「CG と重ねるなら外した方が良いか」→「変えろ」）
- 古写真・ＣＧと重ねる実景（手引きの `vfx` の言葉に当たるカット）は、ミストを「いつも付ける」にしていても「外す」案にした（`kitPlan`）。理由：にじみが画に焼き込まれて輪郭に合わせにくく、上に重ねる CG だけがくっきりして柔らかさが食い違う。柔らかさは合成のあとに編集で実景と CG にまとめて足す。そのカットではレンズを選ぶときにミストの径を条件にしない。根拠は技術の手引きの新しい項目 `t_mist`（ミストの昼間の効き方と合成。出典はデジカメ Watch・Focus Nordic・Roger Deakins のフォーラム・WeVideo）。
- 機材の画面の「いつも付けるフィルター」の下に、この例外を書いた。
- 第9版では、案のある40カットのうち17カットが外す案になる（S#2 C2・C3・C5、S#3 C1〜C3、S#4 C2・C3・C5、S#5 C1・C2、S#6 C3・C4、S#8 C1、S#10 C3、S#11 C1、S#12 C2）。同じシーンで付けるカットと外すカットが混ざるので、編集で柔らかさを合わせる。
- 合成のやり方そのもの（決まった手順）を書いた資料は見つからなかった。外す判断は、上の出典と理由からの判断。
